# 网页取证

"我记得这个 API 是这样的"——这句话在技术问答里是最常见的错误来源。
这个技能的纪律只有一条：**结论里的每一条外部事实，都要能指到一次真实的抓取结果**。

## 一、抓取

1. `web_fetch` 直接拿正文（服务端抓取，不需要用户打开浏览器 Tab）。
2. 如果 `web_fetch` 报"没有可读正文"（纯图片 / 需登录 / JS 渲染），
   改用 `browser(mode=navigate)` + `browser(mode=read)`：让内置浏览器真渲染一遍，
   正文由前端回传。两条路都失败就如实说"这页抓不到"，**不要**用记忆补内容。
3. 本机与内网地址会被拦截。需要读内网 Wiki 时，说明这一限制并请用户提供文本。

## 二、读三个地方，不要只读正文

| 位置 | 为什么必须看 |
|---|---|
| 版本号 / 更新日期 | 没有日期的技术文档不能作为"当前行为"的证据 |
| 代码示例的完整上下文 | 片段往往省略了 import、前置条件与版本约束 |
| 限制与弃用说明 | "已弃用"往往写在小字里，而用户问的正是它 |

## 三、交叉验证

同一事实至少两个来源，或一个来源 + 一处代码/数据佐证：

- 官方文档写的行为 ↔ 本地代码里的实际调用（`code_find(mode=regex)` 搜 SDK 方法名）
- 文档里的字段名 ↔ 知识库里团队约定的字段名（`kb_search`）

两者冲突时，**不要调和**。直接呈现冲突：文档说什么、代码里是什么、
差异可能来自哪个版本。用户需要知道分歧，而不是一个被抹平的平均值。

## 四、引用格式

- 写清「来源 URL + 抓取时间」；重定向过就写最终 URL。
- 引用原文时用引号，并说明是原文还是你转述。
- 抓取被截断（返回里写着"内容已截断"）时，不要断言"文档里没有提到 X"——
  你只看到了前一部分。要断言没有，得把 maxChars 提高后重抓。
