# 写操作自检

写能力的价值全在"可回滚 + 可复核"上。一旦有一次改错了却说不清改了什么，
用户就会永久关掉这个能力——所以宁可多花两步，也不要省掉自检。

## 一、动手之前（缺一步就别写）

1. **读原文**：`code_view(mode=content)` 拿到要改的那段真实内容。凭记忆写 `oldString` 必然命中不了，
   而命中不了的失败还会消耗用户一次审批。
2. **查调用方，并把结果记成清单**：`code_find(mode=refs)` 搜一遍要改的符号。
   改签名类改动，调用方是范围的一部分。**把 refs 的接收者分组抄下来**
   （`order 3、repo 1` 这样的名单）——它不是读一下就丢的中间结果，
   而是第三步"重放调用点"要对照的基线。没有这份基线，改完只能重新搜一遍然后猜有没有漏。
   同名定义散在多个文件时，抄的是**跨文件收敛表**：每个引用文件对应哪个定义文件，
   以及哪几个文件"无法归属"——改签名时正是这几类最容易漏。
   改动要跨多轮时用 `memo(mode=write)` 存一份：上下文一压缩，抄在对话里的清单最先没。
3. **确认基线**：`code_view(mode=diff)` 看目标文件是否已有未提交变更。有的话要在结论里说明
   "本次修改叠加在既有变更之上"，否则用户回滚时会连自己的改动一起丢。
   返回"未追踪文件"说明这个文件还没进 git，回滚没有基点——这种时候更要先 `code_view(mode=content)` 存一份原文。
   想知道这次动过哪些文件，用 `code_view(mode=status)`（可省略 path）。

## 二、选对工具（顺序即优先级）

| 场景 | 工具 | 说明 |
|---|---|---|
| 改局部几行 | `code_edit(mode=replace)` | 首选。`oldString` 唯一命中才动手，命中 0/多次直接中止 |
| 新建文件 / 整文件重写 | `code_edit(mode=rewrite)` / `fs_write_file` | 整文件重写要求你**已经读完全文**，否则等于把没读到的部分删掉 |
| 运维动作 | `srv_exec` | 只能用模板库覆盖的意图；模板外一律转建议，不许自己拼命令 |

`oldString` 的写法：从读到的原文里**整段复制**（含缩进与前后的空行边界）。
只取一行的话很容易命中多处；带上前后各一两行做锚点通常就够了。

## 三、写完之后：三条证据，缺一条就不算验证过

写入工具的返回里自带**改动片段**（`改动片段 @@ -旧 +新 @@`，带上下文行）。
它替代了"我改了什么"的口头复述——**复述不是证据，片段才是**。

1. **对片段**：确认改的是定位单（见 `code-navigator`）里那一处，而不是相邻的类似行。
   只读片段，不要顺手把没看的代码也描述一遍。
2. **重放调用点**：把定位单里记下的 refs 名单再跑一次 `code_find(mode=refs)`。
   改的是签名/返回值时，**每一处引用都得跟上**——引用数下降、或某条被改成"定义"，
   都说明有一处没改到。这是唯一能证明"调用方没漏"的动作。
3. **看结构没坏**：`code_view(mode=outline)` 确认符号还在、起止行合理。
   改大括号/缩进时的典型事故是方法被吞进上一个方法里——大纲里它会消失。

四种返回要分清，它们对应的下一步完全不同：

| 返回 | 含义 | 下一步 |
|---|---|---|
| 改动片段 | 真的改了这几行 | 对片段、重放调用点 |
| 「空操作」（前后逐字节相同） | **磁盘没有变化** | 别写"已修改"，先确认是不是参数传错了 |
| 「超过片段上限，不给片段」 | 改了超过 40 行 | 按返回里的 `offset/limit` 用 `mode=content` 读那段 |
| 「新建文件，没有基线快照」 | 回滚只能靠删除 | 报告里要说清"回滚需手动删除" |

**`verify` 不等于正确**。工具返回里的 `verify=通过` 只说明"落盘的内容就是打算写的那些字节"，
它不判断改动是否正确。用前者的结论去回答后者，是写能力里最贵的一个错误。

最后给出：文件、行区间、`old → new` 的差异摘要、回滚方式。不要只说"已修改"。

## 四、绝对不做的事

- 不要在一次任务里批量改多个文件而不逐个说明——用户批准的是意图，不是一张空白授权。
- 不要为了让测试通过而改测试断言。发现问题就报告，改不改是用户的决定。
- 不要在 precheck 失败（基线变了 / oldString 不唯一）后"换一个位置试试"。
  失败说明你对文件的理解是错的，先重新读，再决定。
- 不要声称"已执行"——执行结果以工具返回的 `ok` 与执行消息为准，不以你的叙述为准。
