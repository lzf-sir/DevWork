## 6. 输入框能力补齐（@ 引用 / / 技能 / 模型切换）

### 6.1 做了什么

把输入框从"一个文本框 + 三个装饰 chip"改成**真能用的输入框**，三块能力全部闭环到服务端：

| 能力 | 交互 | 真实落点 |
|---|---|---|
| **@ 引用** | 正文里敲 `@` 弹候选（↑↓ 选择、Enter/Tab 确认、Esc 收起）；工具行点「@ 引用资产」同样触发 | 选中后正文写入 `@资产名` + 工具行出现 chip；发送时解析成 `assetIds` 随消息提交；服务端气泡 chip 改为**用户真实挂载的资产名**（原来写死「生产库 / 运营知识库」） |
| **/ 技能** | 敲 `/` 弹「技能 + 命令」两类菜单；技能来自服务端登记表，选中后把方法论模板插入正文（可编辑） | `GET /api/skills` → 技能模板随消息真实发给模型；命令是客户端真动作（切模型 / 新会话 / 导出 / 快捷键） |
| **模型切换** | 工具行右侧模型 chip → 下拉选供应商预设模型 | 会话级覆盖：选择随下一条消息的 `model` 字段提交，服务端 `createGateway(model)` 换模型；不改全局配置；未配 Key 时如实说明"只保存选择、不影响实际调用" |

### 6.2 边界处理（都是真踩到的坑）

- **同名资产**：库里 `order_db` 有 prod / dev 两套，光看名字无法判断指哪一个 → chip 上用环境标签区分（`@ order_db · prod`），文本里手写的同名引用**不猜**，以点选的 chip id 为准。
- **离线兜底不能混进 live**：内置资产表（`生产库`）在库里并不存在，混进候选列表用户就能引用一个查不到的资产 → live 用真实资产表，内置表只在断后端时整体兜底。
- **输入框里 @ 与 / 的触发位置**：邮箱里的 `@`、URL 里的 `/` 不触发；查询词里一按空格就收起候选（与 Slack / Notion 一致）；中文输入法组字期间不弹候选。
- **Esc 的语义**：候选浮层开着时 Esc 只收起浮层，不连带触发全局"中断生成"。
- **chip 与正文必须一致**：点 chip 的 × 会同步删掉正文里的 `@名称`；正文里手动删掉 `@名称`，chip 也跟着消失。

### 6.3 新增与改动

**服务端**
- `server/src/config/skills.ts`（新）：技能登记表。形态是**提示词级 Skill**（方法论模板 + 依赖的只读工具），完整 Skill（含脚本执行与沙箱）按设计 §6 尚未实现，此处不做假；`validateSkillRegistry()` 断言工具真实存在且不是写工具。
- `GET /api/skills`（新）：技能清单，登记表自检不过直接 500 —— 菜单里摆着点了会报「未知工具」的技能，比没有更糟。
- `POST /api/conversations/:id/messages` 与 `/stream`：新增可选 `model` 字段（会话级模型覆盖）。
- `createGateway(modelOverride?)`：覆盖只改本次调用；没有端点或没有 Key 照样退回规则化轨迹。
- 气泡 chips：改为用户真实挂载的资产名（不再写死）。

**前端**
- `src/utils/composer.ts`（新）：触发符识别 / 候选过滤 / 文本替换 / 引用解析等纯函数（零 DOM 依赖，可单测）。
- `src/utils/slash.ts`（新）：斜杠命令表，只登记真能执行的命令。
- `src/components/Composer.tsx`（新）：输入框组件。
- `src/store.tsx`：会话级模型选择（localStorage 持久化，跨重启保留）。
- `src/views/ChatView.tsx`：接入新输入框。
